# KPL 2K v0.2 Tech Spec

## Goal

Strengthen the existing classic and All-Star loops without adding accounts, a backend, hero micromanagement, or another game mode.

## Scope

1. Release safety
   - One command validates source data, narrative data, ratings, all 29 season engines, score invariants, champions, completed brackets, and core SPA routes.
   - Played bracket rows must never contain an unresolved team.
2. Local persistence
   - Custom avatar image data is stored once in the current All-Star custom-player library.
   - History entries reference custom-player IDs and never duplicate avatar image data.
   - Quota failures prune old history first and show a visible warning if saving still fails.
   - Existing v1 state and history remain readable.
3. Sharing
   - Share URLs include the current build version.
   - Old-version links are accepted, but the UI says that the current engine will re-simulate them.
   - All-Star matches without custom players can be restored from a link.
   - All-Star matches with custom players can still export an image; only link copying is disabled.
4. Onboarding
   - The home page offers one quick-start preset that loads a valid team, roster, season, and seed, then starts the simulation.
5. Manager choice
   - A pre-match strategy has exactly three values: stable, balanced, and gamble.
   - Strategy changes match variance only; displayed roster strength remains unchanged.
   - The active strategy is visible in match narration and stored in history/share URLs.
6. Result storytelling
   - Result cards derive achievement tags from actual series paths and scores.
   - Placement is supplied by the engine entry; the UI only retains a fallback for legacy history.
   - Role-aware event pools match top, jungle, mid, marksman, and support records.
   - Stage intros react to finals, elimination matches, losing-bracket runs, win streaks, and roster changes.
   - Offensive player nicknames identified by the text audit are removed.
7. Maintenance
   - BGM has one production source file.
   - Product documentation describes the shipped All-Star mode and v0.2 loop.

## Acceptance Criteria

- `python tools/verify_release.py` exits 0.
- Three representative seeds for every manifest season produce a champion and legal best-of scores.
- No completed tree row contains an empty team or more than one grand final.
- Creating and saving repeated All-Star history does not add avatar data URLs to history JSON.
- Classic and non-custom All-Star links restore their setup; version mismatch is disclosed.
- Custom All-Star results expose image export but not link copy.
- Stable and gamble strategies produce different deterministic results for at least one fixed probe while leaving lineup strength unchanged.
- Desktop and 390 px mobile flows pass visual and interaction checks for home, strategy selection, simulation, result, and share modal.

## Deliberate Limits

- No frozen historical engine bundle is shipped. Old links are re-simulated by the current version after a disclosure.
- No per-series tactical pause is added. One strategy applies to the run to keep the simulation flow fast and the engine contract small.
- Custom avatar image data is intentionally device-local and is not embedded in URLs.
